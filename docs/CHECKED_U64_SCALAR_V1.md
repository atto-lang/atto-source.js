# Checked unsigned scalar v1 (explicit experimental profile)

`compileCheckedU64ScalarV1(source)` emits closed-world ESM with an exported zero-arity `main()` returning exact BigInt. Admitted source: ASCII root functions, homogeneous u64/uint parameters and results, canonical decimal literals, grouping, calls and checked +,-,*,/. All other forms including comments, effects, mixed signed types and recursion are refused; no signed fallback. Expanded call work, expression depth, token and source size are bounded. The profile preserves intermediate overflow and reports a JS RangeError with code integer_overflow or division_by_zero. That is not full typed guest Error/Result/supervision ABI parity.

This is an isolated candidate, not a new default parser or general program-v2 support. The existing restricted parser now lowers to an explicit typed IR bridge; the shared tokenizer and default program-v2 integration remain outstanding. The unchanged shared corpus is from atto-platform-conformance#680, blob 2d41ae576d049ed3a8898c3deacc8d30c705dce8. Run `node --test tests/checked-u64-scalar-v1.test.mjs tests/checked-u64-ir-v1.test.mjs`. Full repository CI, browser execution and other backends remain unverified.

## Typed IR bridge

The source API now delegates to `compileToCheckedU64IRV1(source)` and `compileCheckedU64IRV1(ir)`. The explicit model `unsigned-u64-checked-v1` uses resolved callable/parameter indices, decimal-string u64 literals, homogeneous u64 signatures, and checked binary nodes. `validateCheckedU64IRV1` copies and verifies plain-data input, rejects mixed types, recursion, malformed fields, accessor properties and excessive expanded work. The existing signed program-v2 API and source tokenizer are unchanged; this is not a shared canonical IR schema declaration. Only main is exported, as before.

## Checked unsigned division

The explicit profile now admits truncating unsigned quotient / with the same precedence and associativity as multiplication. Both operands retain exact u64 bits; zero divisors raise RangeError with code `division_by_zero` and message `E_U64_DIVISION_BY_ZERO`. Intermediate overflow and left-to-right operand/argument fault order are preserved. The division helper is emitted only when needed. Raw %, comments, mixed signed types, and general program-v2 still remain outside this profile; no portable Error ABI claim.

Local exact focused tests (Node 22.16.0): 46/46 passed, zero skips. The new division suite executes 256 deterministic division guests (224 values, 32 expected zero-divisor faults), plus boundary, precedence, serialized-IR and fault-order cases. Separately compared 1,024 nondivision emitted artifacts byte-for-byte against the prior compiler; all identical.
