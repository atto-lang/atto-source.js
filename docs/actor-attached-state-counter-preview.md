# Checked scalar Counter actor-state preview — JavaScript worker backend

**Target/source contract**: [atto-spec #127](https://github.com/atto-lang/atto-spec/pull/127), [conformance #113](https://github.com/atto-lang/atto-platform-conformance/pull/113).

**Status: restricted trusted-JS generated-module preview, not general actor or cross-backend parity.** This extension is stacked on the typed-actor receiver work in [atto-source.js #31](https://github.com/atto-lang/atto-source.js/pull/31); it must not overwrite or claim the distinct `receives/sends` work.

The compiler recognizes the exact constrained Counter shape from the portable contract with inline `state {let int count;}` **or** attached `define state on actor Counter as { let int count; }`, a synchronous `on_start` initializing a signed-i64 field (or a static per-instance initializer), `using state.read, state.write`, exclusive `critical-write` checked increment, copied scalar `critical-read`, and a single `ActorMail<int>` receiver. No other state access, user call, arbitrary `await`, `select`, second schema, multi-field graph, escaped binder, additional actor or injected JavaScript is accepted. A validated source program is lowered from parsed tokens to fixed trusted-JS instructions; source text is never evaluated.

The new generated module reports ABI `atto.js.browser.actor-state-counter-preview.v1`. `on_message()` starts one actor instance and admits the single `counter.send(1)` into a private pending mailbox, without executing `receive`. This **does not imply scheduler/actor completion**. A trusted host must explicitly call `on_drain()` to execute the admitted turn. After that, the existing `on_route({actor_id:1,wire_type:'i64',buffer})` accepts a separately authorized 8-byte LE signed-i64 input. A controlled serial run sees `1\\n` from the drained send, then `3\\n` from a route containing 2. Pending sends reject external route with `E_ADMISSION_PENDING` rather than bypass FIFO order.

There is no general scheduler, cross-worker RW lock, guest-exposed lease handle, remote supervisor admission proof or TenantVM enforcement proof. Each `create_tenant` invocation has independent JS closure state. The trusted host remains solely responsible for authenticating routing, tenant identity and Worker termination. `on_stop()` irreversibly retires that instance; checked-i64 overflow rolls back mutation, marks it retired and attaches a supervisor-ready panic record, but does **not** prove supervisor delivery.

The tests use all **13 byte-identical** `.atto` sources from conformance PR #113: three positive sources compile and execute in Node (generated trusted JS, **not WebAssembly**); ten invalid sources must be rejected without a generated module. In addition, focused tests reject wrong actor IDs and wire types, effects, direct field access, source injections, alias escapes, and overflow/restart mistakes. Only mark the JS backend `PARTIAL_JS_PREVIEW` when these exact source tests execute on the current tree with nonempty CI steps; the cross-backend status remains `NOT_EXECUTED` until the portable full actor contract is implemented and proven.

For current branch tests: `npm test`. The original `actor-worker.test.mjs` path must remain unchanged by the dedicated state-mode dispatch.
